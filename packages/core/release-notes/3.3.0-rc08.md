# Pure Admin Core 3.3.0-rc08 — Release Notes

**Released:** 2026-10-22 · **Pre-release** (`npm install @keenmate/pure-admin-core@rc`)

rc08 is the largest release of the 3.3 cycle. It moves core onto the **pure-css 2.0
colour / text contract**, removes every **physical left / right utility**, turns the Sass
variable layer into a **configurable module**, and aligns core, svelte-pure-admin and
keen-pure-admin on **one naming vocabulary**. Most of the breaking changes are renames with
a 1:1 replacement — the tables below are meant to be worked through top to bottom.

The exhaustive, per-change list is in [`CHANGELOG.md`](https://github.com/KeenMate/pure-admin/blob/v3.3.0-rc08/packages/core/CHANGELOG.md#330-rc08---2026-10-22-published);
this document is the upgrade guide and the highlights.

## Upgrade checklist

**Everyone using the CSS**

- [ ] Replace physical utilities: `ml-/mr-/pl-/pr-*` → `ms-/me-/ps-/pe-*`,
      `border-left/right` → `border-start/end`, `rounded-left/right` → `rounded-start/end`
      ([table](#physical-left--right-utilities-are-gone)).
- [ ] Use `.text-muted` for muted text — `.text-secondary` is now the secondary **role** colour.
- [ ] Button alignment: `pa-btn--align-*` → `pa-btn--justify-*`.
- [ ] Tabs: `pa-tabs--centered` → `pa-tabs--justify-center`, `pa-tabs--full` → `pa-tabs--justify-stretch`.
- [ ] KPI bento: `pa-kpi-bento__grid--hero-right` → `pa-kpi-bento__grid--hero-end`.

**Theme authors / custom CSS that reads variables**

- [ ] Rename the token families in [Breaking changes — tokens](#breaking-changes--tokens-themes-and-custom-css)
      (`-color` suffix on roles, `accent` → `primary`, `--pc-text-color-1..4`, palette slots,
      `-text` → `-text-color`, `-ring` → `-outline`).
- [ ] Move the theme entry to the Sass module form
      ([example](#the-variable-layer-is-a-configurable-module)). `@import` still compiles, but
      it silently drops some overrides.
- [ ] Rebuild and compare light **and** dark mode — control outlines, tints, focus halos and
      placeholders now follow the base contract, so a theme may look different without any
      code change ([visible changes](#visible-changes-without-a-migration)).

**JavaScript API users**

- [ ] `position` → `placement` in `pureAdmin.confirm / alert / prompt / custom`,
      `pureAdmin.toast.*`, `toast.dismissAll()` and `pureAdmin.config.toast`.

**Wrapper users (svelte-pure-admin / keen-pure-admin)**

- [ ] Follow your wrapper's changelog — its prop renames follow the
      [naming vocabulary](#naming-vocabulary-wrappers-and-fidelity) below.

## Breaking changes — markup and classes

No aliases are kept for any renamed class — old names render unstyled.

### Physical left / right utilities are gone

They didn't mirror under `dir="rtl"`. Removed in pure-css 2.0.0-rc02; core forwards
pure-css's utilities, so themes stop shipping them too. The replacements are identical in LTR.

| Removed | Use |
|---|---|
| `.ml-*` / `.mr-*` (incl. `-auto`) | `.ms-*` / `.me-*` |
| `.pl-*` / `.pr-*` | `.ps-*` / `.pe-*` |
| `.border-left` / `.border-right` | `.border-start` / `.border-end` |
| `.border-left-0` / `.border-right-0` | `.border-start-0` / `.border-end-0` |
| `.rounded-left` / `.rounded-right` | `.rounded-start` / `.rounded-end` |

`.ms/.me/.ps/.pe` now exist in **both** scales — numeric (`ms-2`) and semantic (`ms-sm`) — and
carry `!important` like every other spacing utility.

### Muted text is `.text-muted`

pure-css 2.0 made `.text-secondary` the secondary **role** colour (a fixed grey), not the
theme's muted text. The text scale is now:

| Class | Token | Use |
|---|---|---|
| `.text-body` | `--pc-text-color-1` | default body text |
| `.text-muted` | `--pc-text-color-2` | supporting / muted text |
| `.text-subtle` | `--pc-text-color-3` | hints, tertiary labels |
| `.text-faint` | `--pc-text-color-4` | the faintest step |

### Layout modifiers use the CSS property name

Props are named after the CSS property they drive (`justify` = `justify-content`,
`align` = `align-items`, `textAlign` = `text-align`), and the classes follow.

| Before | After |
|---|---|
| `pa-btn--align-start` | `pa-btn--justify-start` |
| `pa-btn--align-end` | `pa-btn--justify-end` |
| `pa-btn--align-center` | `pa-btn--justify-center` |
| `pa-btn--align-justify` | `pa-btn--justify-between` |
| `pa-tabs--centered` | `pa-tabs--justify-center` |
| `pa-tabs--full` | `pa-tabs--justify-stretch` |

### KPI bento hero

`.pa-kpi-bento__grid--hero-right` → `.pa-kpi-bento__grid--hero-end`. The grid uses
`grid-template-areas`, which follow the writing direction — in RTL the "right" hero rendered
on the left. Same layout, honest name.

### Canonical shapes tightened (old shapes still render)

These are not breaking for rendering, but the documented shape changed — copy the snippet,
not old markup:

- **Spinner is a `<span>`** — `<div class="pa-spinner">` inside text, a button or a `<p>` is
  invalid HTML (the browser closes the paragraph early).
- **Card title is always `h3.pa-card__title-text`** — other heading levels render, but `h3` is
  the shape every wrapper emits.
- **Timeline is `<ul>` + `<li>`** for every variant (simple, alternating, feed). A
  `<div>`/`<div>` tree still renders, as legacy tolerance.
- **Table actions column comes first** (after the row-checkbox column, if any), as both
  wrappers emit it.
- **Filter card buttons** are ordered toggle → custom → clear → refresh.
- **Pager buttons use SVG chevrons** (Lucide) instead of `‹ › « »`, which sit below the
  button centre; they mirror under RTL.

## Breaking changes — tokens (themes and custom CSS)

Class names are unaffected by everything in this section — only stylesheets and themes that
read or set these variables must rename them.

### Role colours end in `-color`; `accent` is `primary`

| Before | After |
|---|---|
| `--pc-primary`, `-hover`, `-active` | `--pc-primary-color`, `-hover`, `-active` |
| `--pc-secondary` / `success` / `warning` / `danger` / `info` | `--pc-<role>-color` |
| `--pc-accent`, `--pc-accent-hover` | `--pc-primary`, `--pc-primary-hover` |
| `--pc-accent-light` | `--pc-primary-bg-subtle` (+ `-hover`) |
| `--base-accent-color*` | `--base-primary-color[-hover\|-active]` |
| `--base-text-color-on-accent` | `--base-on-primary-text-color` |
| `$accent-color` (Sass) | `$primary-color` |

The manifest / schema category `accent` is now `primary`.

### One text scale

| Before | After |
|---|---|
| `--pc-text-strong` | `--pc-text-color-1` |
| `--pc-text-secondary` | `--pc-text-color-2` |
| `--pc-text-tertiary` | `--pc-text-color-3` |

In dark themes tertiary labels get dimmer (Corporate `#9199a3` → `#64748b`) — that is the
theme's own step 3; tune `$base-text-color-3` if it reads too faint.

### Names state their type

| Before | After |
|---|---|
| `--base-*-ring` (outline width / focused / highlighted) | `--base-outline-width`, `--base-focused-outline`, `--base-highlighted-outline` |
| `--base-*-text` | `--base-*-text-color` |
| `--base-text-on-<role>` | `--base-on-<role>-text-color` |
| `--base-input-clear-*` | `--base-input-icon-color`, `--base-input-icon-bg-hover` |

### Palette slots (theme colours 1–9)

| Before | After |
|---|---|
| `$color-N` (Sass) | `$palette-N` |
| `--base-color-N` | `--base-palette-N` |
| `--pc-color-N` | `--pc-palette-N` |
| `--pc-color-N-text` / `--pc-palette-N-text` | `--pc-on-palette-N-text-color` |

Every `--color-N` **modifier class** (`.pa-btn--color-N`, `.pa-badge--color-N`, …) keeps its name.

### Removed (nothing read them)

`--pa-<role>-border`, `--pa-<role>-text-light`, `--pa-<role>-bg-subtle` (callouts use
`--pa-<role>-bg-light`), `$badge-<role>-bg` / `$badge-<role>-text`, `base-inverse-bg` /
`base-inverse-text-color`, the `base-surface-1/2/3/-inverse` aliases, and the transitional
`$form-gap: $form-scale` default.

## Breaking changes — Sass

### The variable layer is a configurable module

`variables/_index.scss`, `_variables.scss`, `_base-css-variables.scss` and
`_pc-component-variables.scss` use `@use` / `@forward`. Sass deprecated `@import` (Dart Sass 3
removes it); core now builds with **zero deprecation warnings**.

A theme configures the whole vocabulary once — foundation and component variables in one map —
before anything else loads it:

```scss
@use '@keenmate/pure-admin-core/src/scss/variables' with (
  $base-primary-color: #bb0a30,
  $navbar-bg: #000000,
  // … every other override
);

@use '@keenmate/pure-admin-core/src/scss/core';
@use '@keenmate/pure-admin-core/src/scss/utilities';
@use '@keenmate/pure-admin-core/src/scss/base-css-variables' as *;

:root, .pc-mode-light {
  @include output-base-css-variables;
  @include output-pc-css-variables;
  @include output-pc-component-variables;
  @include output-pc-alert-variables-light;
}
```

Old `@import` themes still compile, but the module form is the supported one. **Side effect
worth checking:** overrides now reach every module — the `@import` pipeline silently dropped
some (the shell, parts of tables / input groups / sidebar width), so a migrated theme renders
more like its own settings say. All 16 themes in `pure-admin-themes` use the module form.

## Breaking changes — JavaScript

### `position` → `placement`

The same word the wrappers use for every floating / positioned element. No alias.

| API | Before | After |
|---|---|---|
| `pureAdmin.confirm / alert / prompt / custom` (`modal-dialogs.js`) | `{ position }` | `{ placement }` |
| `pureAdmin.toast.*` (`toast-service.js`) | `{ position }` | `{ placement }` |
| `pureAdmin.toast.dismissAll(…)` | `dismissAll(position)` | `dismissAll(placement)` |
| shared config | `pureAdmin.config.toast.position` | `pureAdmin.config.toast.placement` |

## Naming vocabulary (wrappers and fidelity)

Core, svelte-pure-admin and keen-pure-admin now share one prop vocabulary, documented in
[`fidelity/NAMING.md`](https://github.com/KeenMate/pure-admin/blob/v3.3.0-rc08/packages/core/fidelity/NAMING.md) and enforced by `npm run fidelity:naming`
(668 shared features, 0 mismatches at release). If you use a wrapper, its changelog lists the
concrete prop renames; the rules are:

| Rule | Example |
|---|---|
| Every boolean is `is*` / `has*` / `should*` — native attributes included | `isDisabled`, `isRequired`, `isChecked`, `hasClose`, `shouldWrapHeader` |
| `has*` shows a part; a part that is on by default is turned off with `false` | `hasBorder={false}` (not `noBorder`) |
| Overlays use `isOpen`; gated rendering uses `isVisible` | modal / drawer `isOpen` |
| Plain text is `*Text`; the bare name is the rich slot / snippet | `titleText` vs `title` snippet, `countText` |
| `iconName` is a string rendered through the icon component, next to an `icon` slot | `iconName="fas fa-home"` |
| `variant` is always the role colour; `themeColor` is the 1–9 palette slot | stat `color` → `variant`, fields `color` → `themeColor` |
| `type` = which design, `mode` = which behaviour, `layout` = arrangement, `density` = compact / relaxed | tabs `style` → `type`, card tooltip `mode` |
| `style` is only inline CSS | |
| Layout props are named after the CSS property | `justify`, `align`, `textAlign` |
| `placement` = where the component sits; `<part>Placement` = where a part sits; `position` only for a real coordinate | `labelPlacement`, `iconPlacement`, tooltip `placement` |
| Combinable flags are booleans; mutually exclusive options are one enum | alert `headingSize`, banded `labelWidth`, modal `placement="top"` |

The fidelity fixtures in `fidelity/fixtures/*.json` were renamed to this vocabulary. Anyone
running the markup-fidelity harness against their own wrapper must update their capability maps.

## New features

- **Card title / description tooltips only while truncated.** Put `.pa-tooltip
  .pa-tooltip--floating` + `data-tooltip` on `h3.pa-card__title-text` / `p.pa-card__description`
  and add `data-pa-tooltip-overflow` — `tooltips-popovers.js` shows the tooltip only while the
  text is actually cut off. An empty `data-tooltip=""` uses the element's own text.
  `pureAdmin.tooltips.isTruncated(el)` is exposed.
- **Three new loaders** — `.pa-loader-grid` (3×3 dots pulsing on a diagonal wave),
  `.pa-loader-ripple` (concentric rings) and `.pa-loader-dual-ring` (two counter-rotating arcs).
  Monochrome from `currentColor`, `--lg` size modifier; wrappers expose them as
  `type="grid" | "ripple" | "dual-ring"`. `.pa-loader-wave` is now its own animation
  (bobbing pills) instead of a clone of `.pa-loader-bars`.
- **Slider pager** — `.pa-pager__slider` + the new `.pa-range--lg` give long result sets a thick
  scrubber between the pager controls. With the pure-css Fit engine on the container
  (`pureCss.components.fit.init(el)`), it sheds First/Last, the "/ N" total and Prev/Next as
  space runs out, down to the slider alone.
- **Standalone `.pa-range` sliders** — `range-group.js` wires a `.pa-range` outside a
  `.pa-range-group`: `pa-range:change` (live) and `pa-range:commit` (on release / key step), plus
  `pureAdmin.components.range.setValue(el, v | [min, max])` for silent sync.
- **`.pa-list__item--highlighted`** — a persistent accent-tinted row (unread / highlighted),
  distinct from `:hover`. Wrappers: `isHighlighted` / `is_highlighted`.
- **Split-button items in every role colour** — `.pa-btn-split__item--{primary|secondary|
  success|warning|danger|info}`; wrappers expose it as the item `variant`.

## Visible changes without a migration

Nothing to rename, but pages will look different after the upgrade:

- **Field outlines are darker.** Inputs, selects, textareas, input-group add-ons and
  `.pa-btn--secondary` read `--base-input-border-color` (2.0–3.2:1 against the surface across
  the 16 themes) instead of the divider colour (1.2–1.9:1), so fields no longer nearly vanish.
- **Buttons follow the full role contract.** `.pa-btn--primary` paints `--pa-btn-primary-bg`
  / `-bg-hover` (no more brightness-filter hover), and text on every role fill is the contract's
  derived black / white — a theme's button tokens finally show.
- **One disabled fade** — `--base-disabled-opacity` (0.65) for buttons, checkboxes, radios,
  checkbox-list items, filter cards and ranges (were 0.5–0.65).
- **Radios match the checkboxes** — drawn from the `--pa-checkbox-*` tokens instead of the
  browser's native blue. Disabled works like the checkbox (`.pa-radio--disabled` and/or the
  native `disabled`).
- **Placeholders** read `--base-input-placeholder-color`, the same token the KeenMate web
  components use; the query editor's and command palette's extra opacity is gone.
- **Tints, focus halos, borders and shadows follow the theme at runtime** — primary and role
  tints come from the base contract (10% light / 20% dark by default), field focus halos have
  their own lighter tone, ten rules that baked in a build-time colour now use `var()`, and every
  box shadow uses `--base-shadow-color`.
- **One monospace font** — inline `code`, `.pa-code` and the logic tree read
  `--base-font-family-mono` (was a hard-coded Courier New).
- **Table hover accent** is an inset shadow on the first cell, not a reserved border — no gap,
  no content shift.

## Fixes

- Inputs and selects no longer clip descenders at `sm` / `lg` / `xl`.
- `.pa-input` placeholders were the browser's grey (the rule only covered `.pa-textarea`).
- Settings hints, sheet labels and table item descriptions render in their intended tone again.
- Timeline: long words no longer overflow the content box; single-column layouts no longer
  overlap markers with content (one shared rail mixin, vertical date label); the alternating
  layout collapses by **container** width, so it works inside narrow cards.
- Splitter JS honours theme / inline rail-size overrides (`--pa-splitter-rail-size`).
- Logic tree mirrors under `dir="rtl"`.
- Pager: text between buttons is vertically centred.
- Hover colours that faded out (notification / tooltip links, range thumb) use the darker
  `--pc-primary-hover`.
- Navbar inline search shows its focus border; focusing an input-group field no longer shifts
  the add-on; input-group add-ons are boxed with the field.
- Full-width modal on mobile uses the mobile margin.
- Footer version lines are readable on coloured footers (`.pc-footer__muted`).
- Split-button menu items read a defined text token.
- Snippet comments now name tokens that exist.

## Tooling

  (snake ↔ camel), modulo documented per-component idioms. Enum `produces` can now be an
  option → class map for irregular class names.

  keen modal `data-cancel` / `data-pa-close-on-escape`).
